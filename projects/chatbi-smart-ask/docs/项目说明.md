# 项目说明

本文档用来帮助第一次接手这个项目的人快速理解：页面怎么进、接口怎么分、核心链路怎么走、排查问题先看哪里。

## 1. 项目定位

这是一个 ChatBI 演示原型，核心关注点不是复杂工程化，而是：

- 页面效果直观
- 交互路径完整
- 数据链路可演示
- 能离线运行
- 可以快速修改和二次打磨

因此你会看到这个项目采用了相对直接的结构：

- 后端用 `FastAPI`
- 页面直接用 `Jinja2 + Vue CDN`
- 静态依赖本地化，方便离线演示
- 数据主要依赖本地 SQLite 演示库

## 2. 目录说明

### `app/`

后端主代码目录。

- `main.py`
  - 应用入口
  - 注册中间件
  - 挂载静态目录
  - 注册页面路由和接口路由
  - 暴露 `/health`

- `routers/pages.py`
  - 只负责页面路由
  - 返回 `index.html`、`dashboard.html`、`data_dev.html`、`datasources.html`
  - 这里不处理复杂业务逻辑

- `routers/api.py`
  - 主业务接口
  - 包含登录、运行态、问答、流式问答、SQL 执行、图表上屏、数据源管理等
  - 是首页和 Dashboard 的主要后端入口

- `routers/data_dev.py`
  - 数据开发模块接口
  - 管理任务、版本、运行记录、模拟接入联动

- `services/`
  - 封装业务逻辑和存储逻辑
  - 例如演示库初始化、问数引擎、数据源管理、图表存储、用户管理等

### `templates/`

页面模板目录。

- `index.html`：智能问数首页
- `dashboard.html`：图表大屏
- `data_dev.html`：数据开发页面
- `datasources.html`：数据源管理页面

这些页面都不是传统前后端分离 SPA，而是在 HTML 模板中直接挂 Vue 逻辑，因此改动时建议优先按“页面块 + 状态 + 方法”的方式理解，而不是按组件工程去找。

### `static/`

静态资源目录。

- `app_shell.css`：全局页面样式
- `vendor/`：离线依赖
  - `vue`
  - `ant-design-vue`
  - `echarts`
  - `xlsx`
  - `dayjs`

### `storage/`

运行态数据目录。

主要用于放演示数据库、运行中产生的状态文件等。首次启动会自动初始化演示数据。

### `scripts/`

常用脚本目录。

- `run_dev.sh`：本地启动服务
- `api_smoke.py`：接口冒烟测试
- `run_ui_smoke.sh`：页面端到端冒烟测试
- `run_smoke.sh`：串联执行接口 + 页面冒烟

### `tests/e2e/`

浏览器冒烟测试脚本目录，目前放的是 Playwright 回归脚本。

## 4. 核心业务链路

### 链路 A：自然语言问数

1. 用户在首页输入问题
2. 前端调用 `/api/chat` 或 `/api/chat/stream`
3. 后端通过 `QueryEngine` 做意图识别
4. 如果是闲聊，直接返回文本
5. 如果是查询，生成 SQL 并执行
6. 结果回到前端后展示为表格/图表/分析摘要

### 链路 B：SQL 编辑后再次执行

1. 首页返回初始 SQL
2. 用户可直接修改 SQL
3. 前端调用 `/api/sql/run`
4. 后端再次执行并返回新的结果
5. 前端更新表格、图表和摘要

### 链路 C：图表上屏

1. 首页点击“上屏”
2. 前端调用 `/api/charts/pin`
3. 后端把结果记录到图表存储
4. Dashboard 页面通过 `/api/charts` 读取并展示

### 链路 D：数据开发联动

1. 在 `/data-dev` 启动某个任务运行
2. 后端模拟写入一批新警情到演示库
3. 回到首页重新提问
4. 查询结果能够看到最新写入的数据变化

## 6. 登录与会话

项目使用 Session 中间件保存登录态。

- 登录接口：`POST /api/auth/login`
- 当前用户接口：`GET /api/auth/me`
- 登出接口：`POST /api/auth/logout`

因此如果你在浏览器里看到页面打不开或跳登录弹窗，优先确认两件事：

1. 服务是否启动
2. Session 是否还有效

## 7. 常见排查顺序

### 页面打不开

先排查：

1. `curl http://127.0.0.1:9010/health`
2. `bash scripts/run_dev.sh`
3. 浏览器开发者工具里是否有静态资源 404

### 页面能开但数据不出

先排查：

1. `GET /api/auth/me` 是否 200
2. `GET /api/metrics` / `GET /api/datasources` 是否正常
3. `POST /api/chat` 或 `POST /api/chat/stream` 是否报错
4. `storage/` 下演示库文件是否存在

### Dashboard 没图

先排查：

1. 首页是否已经执行过“上屏”
2. `GET /api/charts` 是否有数据
3. Dashboard 页面是否正常拉取图表列表

### 数据开发运行后首页没变化

先排查：

1. `/data-dev` 页面里任务运行是否成功
2. `GET /api/dev/runs/{run_id}` 是否有日志
3. 演示库是否写入成功
4. 首页是否重新发起查询

## 8. 推荐开发方式

如果你要继续迭代这个项目，推荐按下面顺序理解代码：

1. 先看 `README.md`
2. 再看 `docs/项目说明.md`
3. 再看 `app/main.py` 把入口搞清楚
4. 接着看 `app/routers/pages.py` 和各页面模板
5. 最后看 `app/routers/api.py` / `app/routers/data_dev.py` 以及对应 service

这样理解成本最低。
