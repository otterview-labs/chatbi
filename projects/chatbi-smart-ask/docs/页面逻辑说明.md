# 页面逻辑说明

本文档专门解释 `templates/` 下几个大页面的组织方式，帮助后续维护时快速定位：页面展示区块在哪里、状态数据在哪里、关键动作方法在哪里。

## 总体说明

这个项目的页面没有采用传统前后端分离的组件工程，而是使用：

- 服务端 `Jinja2` 输出 HTML 骨架
- 页面内通过 `Vue.createApp(...).use(antd)...mount(...)` 管理状态和交互
- 页面数据主要来自 `/api` 与 `/api/dev` 接口

因此阅读页面时，建议按下面顺序看：

1. 先看页面顶部布局和功能区块
2. 再看 `setup()` 中的状态定义
3. 再看请求函数和业务动作函数
4. 最后看 `return { ... }` 暴露给模板的内容

## 1. `templates/index.html`

首页负责完整的“智能问数”主链路。

### 主要区块

- 顶部品牌区与用户状态
- 左侧数据源选择区
- 中部实时概览 KPI
- 示例问法区
- 问题输入与发送区
- 查询结果区
  - 摘要
  - 图表
  - 表格
  - SQL 编辑执行
  - 下钻
  - 上屏

### 主要状态

- `me`：当前登录用户
- `metrics`：首页概览指标
- `datasources` / `selectedDatasourceIds`：数据源列表与勾选状态
- `messages`：问答消息列表
- `busy`：统一忙碌状态
- `demoRunning`：一键问数状态

### 内部分区建议

首页文件已经按职责补了注释，阅读时可以按这些区块往下看：

- 状态区：用户、指标、数据源、问答消息
- 会话与消息区：会话切换、消息追加、标题维护
- 结果处理区：摘要、列分析、图表配置兼容
- 数据源配置辅助区：表名/字段/连接串解析
- 数据源维护动作区：新增数据源、建表、上传导入
  - 新增数据源：输入读取 → 前端校验 → payload 组装 → 提交后刷新列表
  - 快速建表：表结构校验 → 示例数据 JSON 解析 → 一次性建表
  - Excel 上传建表：读取文件 → 选择工作表 → 预览 → 提交建表
- 上传建表处理区：字段类型推断、工作表解析、预览
- 结果表格与图表渲染区：表格列、图表实例、销毁与滚动
- 基础刷新与登录区：刷新用户、运行态、指标、示例问法
- 账号管理区：用户创建、删除、密码重置
  - 打开弹窗时先刷新账号列表
  - 删除前二次确认
  - 重置密码时单独弹窗提交
- 交互动作区：发送、运行 SQL、下钻、上屏、重置
- 导出与打印区：导出 Excel、打印 PDF
- 生命周期与持久化区：会话持久化、watch、onMounted

### 关键方法

- `send()`：发送普通/流式问答请求
- `runDemo()`：触发默认演示问答
- `runSql(m)`：执行用户修改后的 SQL
- `pinChart(m)`：把当前结果上屏到 Dashboard
- `drilldown(...)`：对图表结果做下钻
- `confirmResetDb()`：重置演示数据库
- `assistantSummary(result)`：生成结果摘要文案

### 阅读建议

首页文件最大，也最容易迷路。推荐优先搜这些关键字：

- `实时概览`
- `查询结果`
- `SQL（可编辑运行）`
- `send()`
- `runSql(`
- `assistantSummary(`

## 2. `templates/dashboard.html`

大屏页面负责读取“已上屏图表”并展示。

### 主要区块

- 顶部标题与刷新控制
- 自动刷新开关
- KPI 指标区
- 图表卡片区

### 主要状态

- `me`：当前登录用户
- `charts`：已上屏图表列表
- `metrics`：顶部概览指标
- `autoRefresh`：是否自动轮询刷新
- `busy` / `asking`：刷新过程状态

### 关键方法

- `refresh()`：刷新图表和指标
- `refreshMetrics()`：只刷新 KPI
- `renderChart(...)`：渲染单个图表
- `syncRefreshTimer()`：控制自动刷新定时器

### 阅读建议

大屏页面的难点不在业务，而在图表实例管理。重点看：

- 图表实例创建与销毁
- 窗口 resize 监听
- 自动刷新 timer 的启动与清理

## 3. `templates/datasources.html`

数据源管理页面负责查看、筛选、创建和删除数据源，同时展示一些首页概览与示例问法。

### 主要区块

- 数据源列表
- 搜索与过滤区
- 已选数据源计数
- 示例问法区
- KPI 指标区
- 创建数据源表单

### 主要状态

- `dataSources`：全部数据源
- `filteredDataSources`：按搜索条件过滤后的列表
- `selectedDatasourceIds`：当前勾选数据源
- `examples`：示例问法
- `metrics`：指标卡片数据

### 关键方法

- `loadDataSources()`：加载数据源列表
- `refreshMetrics()`：刷新概览指标
- `fillExample(ex)`：把示例问法填入输入区
- `createDatasource()`：创建数据源
- `deleteDatasource(id)`：删除数据源

### 阅读建议

如果这个页面出现问题，先区分是：

- 页面筛选逻辑问题
- 数据源 CRUD 接口问题
- 指标/示例的附属展示问题

## 4. `templates/data_dev.html`

数据开发页面是“模拟数据接入与联动”的展示页。

### 主要区块

- 任务列表
- 任务详情
- 版本管理
- 运行监控
- 联动模拟结果
- 数据开发总览 KPI

### 主要状态

- `tasks`：任务列表
- `selectedTask`：当前选中的任务
- `runs`：运行记录
- `versions`：版本列表
- `versionComment`：版本备注
- `simulateResult`：联动模拟结果
- `runStarting` / `versionSaving` / `simulating`：各动作 loading 状态

### 关键方法

- `loadTasks()`：加载任务列表
- `loadTaskDetail(taskId)`：加载任务详情
- `loadRuns(taskId)`：加载运行记录
- `startRun()`：启动一次任务运行
- `saveVersion()`：保存新版本
- `rollback(version)`：回滚到指定版本
- `simulate()`：模拟联动触发
- `resetDev()`：重置数据开发状态

### 阅读建议

这个页面的重点是“状态切换”和“多面板联动”：

- 选中任务后，详情/版本/运行监控一起刷新
- 启动运行后，运行列表与详情要同步更新
- 回滚版本后，任务详情和版本列表都要一起更新

## 6. 维护建议

后续如果还要继续迭代，建议保持这几个原则：

- 大页面先按“区块”理解，不要一上来按所有函数从头读到尾
- 新增交互时，尽量和已有状态命名、loading 命名保持一致
- 每个页面优先保留一个主刷新入口，避免到处散着请求逻辑
- 改完后优先执行 `bash scripts/run_smoke.sh` 做回归
